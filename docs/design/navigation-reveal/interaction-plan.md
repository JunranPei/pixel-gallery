# 底部导航两侧入口：交互设计提案

2026-10-25。状态：供用户审阅的设计与独立交互原型，尚未修改 Android 应用。

## 需求与现有基础

- 从三点菜单移出 Lock、Hidden。Lock 位于 Photos 左边，Hidden 位于 Albums 右边。
- 常态仅显示 Photos、Albums；手指向右拖导航栏露出左侧 Lock，向左拖露出右侧 Hidden。
- 现有导航是居中悬浮胶囊：选中项显示图标和文字，未选中项只显示图标。保留这一规则和现有应用配色。
- 只改变导航栏自己的形状、内部位置与选中状态。拖出入口不切换页面，不改变顶栏、主体、底部内容留白。
- 本文中的位移、阈值、弹簧参数是提案初值，最终手感由用户确认，不能当作已经实机验收的数值。

## 使用的 skill 与设计准备

已读取并应用公开的 [frontend-design SKILL.md](https://github.com/anthropics/skills/blob/main/skills/frontend-design/SKILL.md)，按先定方向、对照需求、制作原型、审阅的流程进行。本轮不安装新依赖，不调用图像生成，不改变应用风格。

配色沿用截图中的浅色 Material 风格：页面 `#F6F4FC`、主体 `#FFFFFF`、导航容器 `#EFEDF7`、选中项 `#B6C5FA`、主要文字 `#30323D`、次要文字 `#626878`。这是演示配色，正式接入继续读取应用主题，兼容动态颜色和深色主题。

应用内继续使用既有字体、24dp 图标、胶囊圆角；原型外的说明使用系统中文字体。默认导航高度示意为 64dp，按钮触控高度至少 48dp。宽度按文字测量；原型以收起约 200px、单侧展开约 264px 示意。

对照后保留的视觉重点只有一个：像把胶囊内侧藏着的入口拉出来。删去整屏位移、网格视差、发光和按钮缩放等无关效果。导航外的页面保持稳定。

## 推荐布局

方括号代表选中胶囊；无括号的未选中项在实际界面只显示图标。

| 状态 | 排列 |
| --- | --- |
| 常态 Photos | `[Photos]  Albums` |
| 常态 Albums | `Photos  [Albums]` |
| 向右拉出 Lock，仍在 Photos | `Lock  [Photos]  Albums` |
| 向左拉出 Hidden，仍在 Albums | `Photos  [Albums]  Hidden` |
| 当前在 Lock | `[Lock]  Photos  Albums` |
| 当前在 Hidden | `Photos  Albums  [Hidden]` |

不要求先选 Photos 才能拉出 Lock：两个普通页面都能向任意一侧拖，入口次序不变。一次只露出一侧；当前选中的普通页面不会因为拖动而改变。

### 为什么首选单侧三项

| 候选 | 优点 | 代价 | 结论 |
| --- | --- | --- | --- |
| 单侧展开三项 | 能看清拉出了哪一侧；原来两个按钮始终在；宽度克制 | 切换到另一侧先经过收起 | 推荐 |
| 一拖就展开四项 | 两个入口一次可见 | 没有被拖的一侧也出现；手机上占宽较多 | 保留为备选，不作为默认 |
| 两侧各弹出一个独立小球 | 中间胶囊几乎不移动 | 看起来像额外悬浮工具；需跨空隙点击 | 不建议 |

## 每一步的变化

| 阶段 | 手指/用户动作 | 胶囊与按钮 | 页面、反馈与下一步 |
| --- | --- | --- | --- |
| 0 收起 | 无操作 | 只有原来的两项；隐藏入口完全裁切，不露边、不占点击区 | 原页面正常显示 |
| 1 按下 | 在胶囊内任意位置按下 | 不预先展开、不浮起、不抖动 | 沿用原按压反馈；此时仍可成为一次点击 |
| 2 识别方向 | 横向移动超过触摸阈值，且明显大于纵向移动 | 从当前位置开始跟手；不先跳一格 | 正式接入使用系统 touch slop。原型用 8px、横向超过纵向约 1.2 倍示意 |
| 3 拖出 | 右拖/左拖 | 整个胶囊小幅同向偏移，原来两项连续让位；左 Lock/右 Hidden 从内侧裁切边界露出。所有图标保持原尺寸 | 内容区仍不动、不切页；横拖不会同时触发主页 Pager |
| 4 接近停靠 | 拉到有效展开距离 | 容器宽度逐步增加约一个图标槽；后段位移增益降低 | 越拉越有阻力。首次越过展开阈值可给一次很轻的触觉反馈；原型不模拟硬件震动 |
| 5A 松手不足 | 未到阈值，速度也不足 | 沿当前速度回弹收起，隐藏入口逆向退回裁切区 | 不导航、不弹出任何页面 |
| 5B 松手足够 | 超过阈值，或有明确的短促甩动 | 自动补足展开；整体跟手偏移回到中央，三项排列稳定 | 只展开入口，不自动进入 Lock/Hidden |
| 6 停靠 | 手指离开 | 三项保持可见，原来的当前项仍选中 | 不设倒计时，不会刚看清就消失 |
| 7 点击入口 | 点击已完整露出的 Lock/Hidden | 选中底色向目标连续移动；原文字收回、新文字展开；三个按钮的总宽度保持稳定 | Lock 进入现有认证流程；Hidden 使用现有隐藏相册页。认证失败/取消回到原普通页面，保持 Lock 入口已展开以便重试 |
| 8 私有页面根部 | 已进入 Lock/Hidden | 当前项显示文字，两个普通项仍可点；当前入口固定可见 | 不提供通过拖动偷偷藏掉当前选中入口的行为。横拖只给轻微阻尼反馈，放手回原位 |
| 9 返回普通页 | 点击 Photos/Albums，或系统返回 | 当前页选中态转移，同时对应侧入口收回；胶囊恢复两项 | 点击去指定普通页；系统返回去进入前的普通页。保留原滚动位置、搜索和网格列数 |

原型中的 Lock/Hidden 页面只是布局示意，不接触真实文件，也不模拟认证成功。

## 藏回去的规则

推荐采用明确动作触发的收回，不设置自动消失计时。

1. **反向拖动**：已展开 Lock 时向左拖、已展开 Hidden 时向右拖，先收回当前侧。一次手势最多抵达收起，不在同一次手势末端突然露出另一侧；再拖一次才展开另一侧。
2. **点普通导航项**：执行原本的切页，并收回侧入口。点已选中的普通项也可只收回。
3. **继续操作主体**：在普通页面点击内容，或开始明确的纵向滚动时收回；同一个触摸事件继续执行原来的打开/选择/滚动操作，不吞掉第一次点击。原型的“操作主体时收起”开关可比较手动收回方案。
4. **系统返回**：普通页且入口展开时，先只收起入口；当前位于 Lock/Hidden 时，先返回进入前的普通页并收起。之后的返回行为仍遵循现有应用。
5. **离开本层**：进入详情、Settings、选择状态或 Quick Sort 等使导航原本不显示的状态，沿用现有显示规则，并清理未完成的拖动。返回普通页时从收起状态恢复；返回 Lock/Hidden 根部时仍显示当前选中入口。
6. **不要把当前页入口藏掉**：正在 Lock/Hidden 时，不因操作网格、等待、滚动或反向拖动而把当前选中项消掉。用户点普通页或返回后再收起。

不推荐“松手立即收回”：松手之后没有稳定点击入口的机会；除非另改为拖动直接导航，而那是另一种交互。

## 阻尼与动画约定

### 跟手阶段

- 基础位移来自手指，不能每帧另起一段固定时长动画追赶手指。
- 有效拖动范围示意 112dp；前段反馈敏捷，后段位移增益逐渐降低。可用连续单调曲线 `p = 0.8u + 0.2(2u - u²)`，`u = clamp(distance / 112, 0, 1)`。
- 容器约增加一个未选中槽位宽度加间距；整体跟手偏移最多约 12dp。按钮、文字、图标本身不缩放。
- 超过全展开后，只允许小幅额外弹性位移，越拉收益越小，绝不无限伸长。
- 隐藏项从容器裁切边缘连续进入；可配合短区间透明度辅助，但不能滑完才突然出现。

### 松手阶段

- 初始提案：展开进度至少 55%，或拖动至少 24dp 且沿该方向速度超过约 700dp/s，才展开；否则回到起点。
- 已展开时，反向收回也使用对应距离/速度门槛；未满足则回到展开位置。
- 弹簧提案：阻尼比约 `0.9`、刚度约 `520`，把松手速度交给弹簧。收敛通常约 220–340ms，具体随速度和距离而变，不把时长作为硬限。
- 只允许一次非常轻的回弹，避免多次晃动；容器中心回位和展开进度使用同一套运动时间，不做彼此打架的动画。
- 重新按下可立即接管当前视觉位置；反向、取消、连点都从当前值继续，不跳回预设起点。

Android 官方说明了 [`spring` 的阻尼、刚度与中途改变目标时的速度连续性](https://developer.android.com/develop/ui/compose/animation/customize)。这里的具体参数和阈值是本提案，不是官方规定。

### 选中项切换

- 继续使用原来的“选中显示文字，未选中只显示图标”。
- 选中底色平移并变宽；文字随分配宽度展开/收回，不挤压图标，不让导航突然变宽。
- 同样三个可见项之间切换，总宽度稳定；切回普通页时才收掉侧槽。
- 切页不加入新的网格缩放、顶栏淡出或主体上下移动。沿用已验收的页面切换机制。

## 手势冲突与边界

- 只从胶囊的实际可见区域接横向手势，不扩大成屏幕底部整条拦截区；不占用系统底部返回主屏手势区。
- 横向识别成功后，本次手势不再触发导航按钮点击，也不传给主页左右切页。
- 未越过阈值的点击仍由原按钮处理。纵向手势继续交给既有滚动逻辑。
- 初始选择 Photos 或 Albums 都允许双向展开；Lock 固定左、Hidden 固定右，不随当前选中项交换。
- 导航已被现有纵向滚动行为隐藏时，不在空白区域保留横向命中区。拖出中的导航暂时保持可见，结束后恢复原滚动隐藏规则。
- 多指、系统取消、切后台、旋转：取消此次拖动，回到开始前的合法停靠状态；不触发隐藏页面导航。
- 半展开和收起的隐藏项不可点击、不可获得键盘焦点，也不暴露为可访问入口；完整展开之后再开放。
- 放大字体时优先保证 48dp 触控区，减少间距并按可用宽度测量选中文字；不得把三个按钮缩成小目标。窄屏仍只展开一侧。
- 无障碍：常态胶囊提供“展开 Lock”“展开 Hidden”辅助操作；展开后提供“收起额外入口”。桌面原型支持聚焦导航后方向键展开、Escape 收起/返回，按钮支持 Enter。
- 减少动画偏好：保留拖动直接反馈，松手使用无弹跳的短收敛；不通过新增弹跳表达状态。

## 交互原型的范围

`index.html` 是独立的可拖动演示，包含普通状态、展开停靠、点击进入页面示意、返回、反向收回、慢放、阻尼调节和主体操作收回开关。无外部依赖，不连接 Android 应用，不读取真实媒体。

待用户决定：采用单侧三项还是两侧四项；主体操作是否自动收回；当前私有页面入口固定可见这一规则；阻尼和展开阈值的最终手感。其余明确要求不等待这些取舍才能继续设计。
