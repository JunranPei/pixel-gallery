# 持久化增量去重

日期：2026-10-19。

## 行为

打开去重时，先显示数据库中已有的重复组，标注“已显示上次结果 · 正在检查变动”。此时选择与清理操作均不可用，检查完成后才允许清理；更新尚未完成时不显示“没有重复”。

每次仍核对当前范围的媒体清单和文件状态，但不再默认完整读取每个文件：

1. 从文件系统取得实际大小，不以可能滞后的 MediaStore SIZE 列排除候选。
2. 实际大小相同、且属于当前比较范围的文件，先比较前 64 KiB 的 SHA-256。小于等于 64 KiB 的文件在这一步已经完成完整内容校验。
3. 前缀也相同的大文件才计算完整 SHA-256。只有实际大小和完整指纹均一致才归为重复；前缀相同本身不能确认重复。
4. 在独立的 `duplicate-content-index-v1.db` 中保存文件状态、前缀指纹、完整指纹。没有重复候选的文件只保存状态，不提前读取内容。
5. 后续复用状态未变化的记录；新增文件若与以前唯一大小的文件形成候选，也会补查相应旧文件。已完成的全库检查清理不在当前输入范围内的旧索引，相册检查保留其他相册索引。

内容索引以物理路径作为文件缓存键，避免 MediaStore 的 external/external_primary URI 别名引起重复读取。状态签名包含存储设备、inode、实际大小、修改时间和状态变更时间的纳秒部分，并在可用时包含 MediaStore 版本。覆盖后恢复旧修改时间仍会改变状态变更时间。读取前后状态不同的文件被跳过，不保存新的内容指纹。

纳秒时间字段从 API 27 起可用，详见 [Android StructStat 文档](https://developer.android.com/reference/android/system/StructStat)。API 26、缺少亚秒状态时间的文件系统，以及无法取得可靠文件状态的来源不跨次复用指纹；仍使用实际大小筛选，无法取得大小的流则回退完整读取。索引不可读或写入失败时继续执行不依赖缓存的内容检查，不把索引异常当成“没有重复”。

索引独立于保存收藏、标签的图库数据库，无需改动原有数据库结构。缓存写入按批次提交；取消后有效检查点可在下一次继续使用。未变动的记录不重复写入。

## 清理

浏览阶段的缓存不能授权删除。原有 `MediaDeduplication.validate` 继续重新打开本次选中的副本和保留件，计算完整指纹；权限申请后也会再次核验，再按路径、修改时间及未在回收站的条件提交更新。不会为了清理少量副本重读整个图库。

## 验证

- 140 项单元测试通过，其中 17 项新增测试覆盖持久索引复用、同大小覆盖、旧 SIZE、前缀相同但尾部不同、增添候选、移动与相册范围、URI 别名、删除、取消和清理前独立核验。
- 150,000 条合成记录、各自具有不同的实际大小：首次与重复检查均不读取媒体内容；重复检查复用 150,000 条状态记录。这是算法规模测试，未测量真机 15 万个文件的文件系统访问延迟。
- Android 模拟器上的真实 JPEG：重建仓库对象并重新读取 SQLite 后，未变化的文件读取内容为 0 字节；同大小覆盖并恢复原修改时间只读取改变的文件。
- 在旧相册快照产生后新建 keep-both 副本，刷新后的相册扫描包含三份相同内容，只有新增副本需要读取；移除副本后不再把它计入重复组。
- 更新中的旧结果显示标记且没有清理按钮。明暗主题审阅与确认、实际移入回收站及保留件字节完整性均通过模拟器检查。
- 相册搜索修复此前已通过左右滑入、短滑取消、返回、分类交集与大图翻页回归。

构建与测试记录：`scratch/incremental-dedup-build-final.log`、`scratch/incremental-dedup-unit-final.log`、`scratch/incremental-dedup-ui.log`。模拟器为独立的 `GalleryAlbumSearchQA20261019`。

## 性能边界

后续仍有清单、文件状态和数据库核对的耗时；本次实现消除的是未变动媒体的重复内容读取，不能承诺任意规模图库均为零毫秒。更新由用户打开去重页触发，在 IO 后台执行；已有重复组先行显示。尚未进行真机 15 万媒体的端到端计时。

## 扫描进度和空结果修正

- 原实现在核对完整清单和比较整组候选文件结束前不更新计数，容易长时间显示 0。现在区分准备清单、核对信息、候选比较及完整验证；信息核对阶段即更新数量，内容读取期间约每 100 ms 发布已读字节数，单个文件验证完成后更新计数。
- 相册范围直接查询 MediaStore 当前记录，不再先触发整个图库的 Room／图片索引同步。单相册查询限制目录并排除子目录，全部相册按完整父路径分别比较。查询异常不会用空列表冒充正常结果。
- 无重复页仅保留状态图标、简短结论及检查数量。存在未核验文件时显示“未能完成检查”和数量，不显示“未发现重复文件”。取消、部分失败以及已有缓存结果的清理限制继续保留。
- 142 项单元测试通过。真实菜单入口的模拟器回归确认：全部相册 7 个文件、3 个相册内重复组；单相册 4 个文件、2 个重复组。仓库层测试另覆盖旧快照之后出现的第三份 keep-both 副本、单目录查询隔离、各阶段进度、不可读文件、明暗空结果页和真实回收站操作。
