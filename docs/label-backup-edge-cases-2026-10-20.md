# Label backup 边缘情况与验收

本轮先查官方资料，再执行单元测试、真实文件/隔离数据库测试和实际系统文件选择器测试。仅新增本轮测试数据；不删除已有照片、标签和先前 318 文件测试集。未验证的环境不得标记通过。

## 搜索依据

- [RFC 8259](https://www.rfc-editor.org/rfc/rfc8259)：对象重复键存在互操作歧义；还须检查完整 JSON、UTF-8、数字范围与字符串编码。
- [Unicode normalization FAQ](https://www.unicode.org/faq/normalization.html)：视觉相同的文本可能具有不同编码，需覆盖规范化后标签名称冲突。
- [Android Storage Access Framework](https://developer.android.com/training/data-storage/shared/documents-files)：URI 可能来自本地、SD 卡或云端；权限和读写可能失败；Create Document 重名会生成新文件。
- [SQLite atomic commit](https://www.sqlite.org/atomiccommit.html) 与 [Room withTransaction](https://developer.android.com/reference/androidx/room/RoomDatabaseKt)：恢复失败、取消或冲突时不能留下半套标签关系。
- [restic integrity verification](https://restic.readthedocs.io/en/stable/045_working_with_repos.html)：目录或记录存在不等于内容完整，须覆盖内容读取、校验与实际恢复。

以下是依据这些资料和本项目内容哈希匹配方式制定的测试，不代表上述来源对本项目的结论。

## 发现与处理

| 问题 | 修复前证据 | 处理与复测 |
| --- | --- | --- |
| JSON 读取过于宽松，重复字段会被后值覆盖，未检查异常 Unicode 与嵌套深度 | `scratch/label-backup-edge-baseline.log`：66 项相关单测中 8 项失败；原始 XML 保留在 `scratch/label-backup-edge-baseline-results/` | 改为严格读取，拒绝重复字段、未配对代理字符、尾随内容和过深嵌套；修复后完整 209 项单测通过，其中标签备份 67 项 |
| 预览后变成排除目录仍继续恢复 | `scratch/label-backup-edge-device-baseline-details.txt` 中 D04 | 恢复前重新检查当前可用库；修复后的该设备用例通过 |
| 最后一个文件的进度回调取消导出后，仍会写目标文件 | 同上 D07 export | 写入前、分块写入中及返回前补取消检查；最终设备用例通过，取消后目标未写入/事务无新增记录 |
| 取消恢复时仍提交新标签 | `scratch/label-backup-cancellation-baseline-probe.log`：取消后数据库多出两个新标签 | 事务中逐标签、逐批关系和提交前补取消检查；最终设备用例通过，取消后目标未写入/事务无新增记录 |

测试工具本身的问题单独记录，不计作应用缺陷：第一次跨系统文件选择器点击使用了只针对本应用的事件注入；已改用 UiAutomation。故障提供器首次用 Kotlin 编写，独立测试进程缺少目标应用运行库；已改用只依赖 Android/Java 的测试提供器，原中断记录为 `scratch/label-backup-edge-provider-harness-result.log`。

容量约束：单份备份最多 5,000 个标签（含收藏）、100,000 个媒体记录、2,000,000 条关系，输入上限 64 MiB。它们是备份文件限制；本地积累或多次合并后超过这些容量，导出可能被拒绝，不会自动拆分备份。本轮不将这些限制宣称为无限容量支持。

## 最终结果与证据

- 单元测试 209 项，失败/错误/跳过均为 0；其中标签备份 67 项。100,000 条完整合法媒体记录接受、100,001 条拒绝；2,000,000 条关系接受、再多一条拒绝。日志：`scratch/label-backup-edge-unit-final.log`。
- 仓库设备测试共 23 个用例组通过：主批 20 组、移动/实际重压缩 2 组、恢复再导出 1 组；另有更严格的 UTF-8/64 MiB 输入复测与原迁移回归通过。完整日志列于 `scratch/label-backup-final-verification.json`。
- 系统文件选择器及产品备份弹窗测试通过。弹窗截图使用隔离数据库与测试宿主背景，不能作为完整 Library 布局证据；截图：`scratch/label-backup-edge-ui-qa/`。实际应用 Library 截图：`scratch/ui-label-migration-qa/label-edge-final-library.png`。
- 先前 318 个媒体文件逐一与原始样本比较 SHA-256，0 个变化；`scratch/label-backup-retained-media-verification.json`。测试没有使用生产照片或标签作为可修改夹具。
- 安装 APK 与本次构建 SHA-256 相同，全部产品源码早于 APK，见最终验证 JSON。
- 没有实际执行云端断网、SD 卡拔出、真实磁盘写满、系统强杀/断电；流及事务故障注入不能替代这些环境。当前只验证此模拟器系统及默认字体环境。

后续复制/移动修复版本又通过了原标签迁移设备回归（`scratch/copy-move-label-final-regression.log`）。当前最新安装 APK 校验以 `scratch/copy-move-final-verification.json` 为准；上面的标签备份验收 JSON 保留为该阶段原始记录。
