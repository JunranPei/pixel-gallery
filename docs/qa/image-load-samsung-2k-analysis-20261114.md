## 2K 导致的解码路径变化

8 张 `image_5364491107960865_*.jpg` 在 FHD+ 时原生解码成功，在 2K 时原生尝试快速失败并进入标准路径。分别为后缀 01、03、04、05、06、07、08、09。

源码 `indexed-jpeg/src/main/cpp/preview_jpeg_jni.cpp` 按实际适屏尺寸选择 1/8、1/4、1/2 或全尺寸解码；原生 RGBA 中间位图上限为 32 MiB。按这 8 张的源尺寸和 1440×3120 目标计算，采样从 1/4 变成 1/2，所需位图为 36,341,640–44,761,088 字节，全部超过 33,554,432 字节上限。此前 1/4 输出宽度为 1305–1394，能够覆盖 FHD+ 的适屏宽度。

这些数值将路径变化定位到原生中间位图的分配上限。该判断由实际失败/回退日志、源尺寸及源码分支共同得出，本次没有修改该上限。

## 调度与放大记录

在上述 18 张与一加对应的原生输出相同 JPEG 上，系统轨迹保存区间内原生工作运行时间为 2620.618 ms，其中 CPU 6、7 合计 2342.893 ms，约 89.4%；按实际运行时间加权的 CPU 频率为 3491.976 MHz。原生工作结束至预览就绪阶段保存的源线程运行均位于 CPU 6、7，加权频率为 3526.570 MHz。频率统计为实际执行记录，未进行改变线程调度的受控复测。

本次最后一次东汉地图打开（entry 97）包含放大操作，捕获 34 次完成的 `PLATFORM_REGION_DECODE`，耗时 410–964 ms，中位数 659 ms。对应执行器有 35 次提交、开始和结束；未将执行器任务数等同于成功区域解码数。一加此前没有对应的区域解码完成记录。
