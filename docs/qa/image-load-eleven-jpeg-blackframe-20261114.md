# 指定 11 张 JPEG 的黑帧与低内存交接验证

本页窗口等待实验已被否决。用户指出延后详情页首帧造成点击后的停顿，要求沿用三星旧版立即打开且几乎无黑帧的体验。开页等待及其回调已从源码移除；原生逐行适屏缩放保留。以下 22 次零黑帧是这项已否决实验的历史记录，不作为当前方案的验收结果。

## 实测结果

一加 CPH2745，普通模式，`high_performance_mode_on=0`。电脑提供的 11 张原图与手机现有文件逐一 SHA256 相符；未复制或替换手机相片。Samsung 当前未连接，同组照片的三星逐帧对照尚未进行。

保留正式版 `com.pixel.gallery.multitask` 4.3.6.6（versionCode 4083，2026-11-10 安装）的现有缓存，每张连续打开两次，共 22 次。录屏解码 1,298 帧，中央照片区域检出 160 个全黑帧，共 20 段。首次 11/11 有黑帧，153.4～342.2 ms；立即再次打开时 9/11 有黑帧，9.8～31.8 ms。视频画面中详情页工具按钮已出现，照片区域为空。

正式版未启用请求来源日志，表中“第二次”按操作顺序定义，未记为已证实的 MEMORY_CACHE 命中。没有清除正式版缓存、改动其设置或安装替换包。

## 交接处理与验证

详情页此前能在缩略图完成前提交黑底。新实验在导航切换前注册现有窗口的 pre-draw gate，等当前照片的过渡缩略图或完整预览交付后再放开首帧。保留上一帧由窗口系统完成，没有复制图片、保存网格截图或增加图片缓存。1500 ms 超时仅用于失败恢复，本轮 22 次均通过内容交付释放，超时 0 次。

该实验只在 `NATIVE_EXACT_FIT_PROBE=true` 的独立无缓存诊断包生效。正式版默认不开启，正式 APK 保持原安装。过渡图保留；例如 09 图首轮缩略图于点击后 381 ms 就绪，窗口于 398 ms 放开，清晰预览于 487 ms 就绪，存在约 89 ms 的缩略图显示阶段。

同时将诊断分支的 `configured.listener(trackedDrawableListener)` 改为 `addListener`，避免覆盖前面注册的缩略图 opening-ready 与 entry-ready 回调。

同一批 11 张照片，每张两次共 22 次，在全部图片缓存关闭下重新读取原图。22 次完整预览来源均为 LOCAL，22 次都走原生 JPEG 路径，最终位图尺寸与原生输出一致。录屏解码 1,332 帧，按同一中央区域、`blackframe=amount=98:threshold=32` 检测为 0 黑帧，并查看首轮交接联系图。没有用缓存缩短或隐藏源读取。

此对照包含低内存缩放与窗口交接两项实验；两版不是仅差窗口交接的严格单变量实验。当前证据支持一加打开页的可见交接空档，尚未取得本组在三星上的逐帧数据。

## 低内存缩放

原生 JPEG 解码时顺序读取并缩放到最终适屏位图，仅另用两行像素与横坐标映射。原来 3750×5000 的三张样本，最终仍为 1272×1696、8,629,248 字节；没有保留 1875×2500 的较大输出。11 张指定样本按各自比例输出 4,314,624～9,707,904 字节，均未再生成第二份 FitCenter 位图。

已有同一原生实现的 25 组像素检查通过，包含单像素、窄图、奇数尺寸与取消检查；与 Android createScaledBitmap 的最大通道误差为 1。三张实图每种方式三次，共 18 次，最终输出均为 8,629,248 字节；采样 native heap 增长中位数由 31,835,856 降为 10,901,712 字节。这是同循环函数测试的增量采样，未写成整应用总内存。

## 构建与留存

首轮构建在打包阶段 Java 本地内存分配失败。将 Gradle heap 从 2G 降为 1200m 后，`:app:packageRelease` 成功，日志为 `scratch/image-scheduling-probe/exact-entry-gate-build-retry.log`。

该实验 APK 已标为 `artifacts/PixelLoadDiagnostic-exact-fit-delayed-rejected.apk`，31,063,818 字节，SHA256 `93464fdf6dab07cdf4767f82b8b8fcc591634ef20ba13446f2c10dfe2d082fd1`；当时手机已安装文件 SHA256 与之相符。使用独立包名 `com.pixel.gallery.loadtrace.nocache`。

原有 `exact-final-ui-summary.json` 的黑帧字段使用阈值 8，漏检视频 YUV 有限范围的黑色。已改为阈值 32 重算并更正为修复前 20 帧，注明由本次交接修复记录取代。

主要原始材料位于 `scratch/image-blackframe-user-20261114/`：
