## 频率上限与核心选择

开启前记录到的最常见组合为 CPU 0–5 上限 2.3616 GHz、CPU 6–7 上限 1.8624 GHz；开启后该组合在快照中未出现。

开启后共 188 个采样快照，187 个有完整的两组上限。CPU 0–5 上限为硬件报告最高值 3.6288 GHz 的快照有 148 个；CPU 6–7 上限为 4.608 GHz 的有 119 个。CPU 6–7 仍有 17 个快照上限为 2.4384 GHz，其余动态取值见 `cpu-limits-analysis.json`。

518 条完整 Glide 源线程记录均位于 `/top-app`，允许 CPU 0–7，有效 uclamp 为 0–1024。优先级 129 有 489 条，139 有 29 条；统计包括空闲线程快照。

同一批 28 张 JPEG，系统轨迹中原生工作覆盖关闭模式的 26 张、开启模式的 27 张；保存执行区间的 CPU 6–7 运行占比从约 19.6% 升到 79.2%，按实际运行时间加权的频率从 2.322 GHz 升至 3.383 GHz。原生工作结束至预览就绪的源线程加权频率从 2.392 GHz 升至 3.540 GHz。

这些记录把此次适屏 JPEG 差异定位到性能模式对应的频率和核心安排；本次没有修改 APK、线程优先级或线程允许核心集合。
