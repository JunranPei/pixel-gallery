# 一加与三星图片加载过程对照

## 数据与配对

两台使用同一诊断 APK，SHA256 均已在设备安装文件回拉后核对。包名为 `com.pixel.gallery.loadtrace.nocache`，versionCode 4085。

- 一加 CPH2745，Android 16。39 次进入、39 个预览请求、39 个完成；保存 8 段系统轨迹。
- 三星 SM-S9380，Android 17。47 次进入、48 个预览请求、47 个完成；包括一次同一详情会话内的切换。1 个请求在完成前 dispose，未纳入完成耗时比较。保存 8 段系统轨迹。
- 两台所有完成预览的来源均为 LOCAL。
- 两台本次都没有 PLATFORM_REGION_DECODE 完成记录，也没有 SSIV 瓦片任务启动；当前结论覆盖适屏打开过程。

对照文件按文件名、尺寸、MIME 和精确字节数配对。三星部分名称增加了“ (1)”复制后缀，配对时只忽略扩展名大小写和末尾数字复制后缀，原名和路径原样留在证据中。得到 35 组完成请求，其中 25 组原生 JPEG 输出尺寸相同、10 组均回退标准 JPEG 路径。尚未核对两台原文件的完整 SHA256，不能将元数据配对写成文件哈希验证。

排除了一加独有的两张已打开 JPEG、三星未完成的一个对应请求，以及名称、字节数不一致的日本地图 PNG。PNG 两侧字节数为 57,672,855 与 72,911,658，未将其作为同文件对照。

## 25 组同尺寸原生 JPEG

各行分别统计同一批 25 个配对文件，数值为中位数。中位数不相加当作某一张图片的过程。

| 阶段 | 一加 | 三星 |
|---|---:|---:|
| 点击到清晰预览请求发起 | 126 ms | 89 ms |
| 请求发出到原生任务开始 | 1 ms | 0 ms |
| 原生 JPEG 解码调用 | 175.122 ms | 100.603 ms |
| 解码调用内线程 CPU 时间 | 171.568 ms | 98.726 ms |
| 原生工作结束到预览回调就绪 | 69 ms | 17 ms |
| 预览就绪到预绘制 | 5 ms | 7 ms |
| 点击到清晰预览预绘制 | 379 ms | 222 ms |

同一 APK、同一批源尺寸与字节数匹配的输入、相同的原生输出尺寸，解码调用阶段已存在执行时间差。额外时间主要体现为 CPU 执行。

适屏后处理的输出不同：一加视口 1272×2772、三星 1080×2340。多数图片的最终适屏宽度分别为 1272 与 1080，像素数约相差 1.387 倍。该差异会影响后处理工作量。两台系统版本也不同，解码后的缩放、资源初始化等具体函数尚未逐一计时。

前置主线程阶段还存在图库数量差异：一加 All 为 131,370 项，三星为 100,364 项。未将前置阶段全部差异直接归到硬件或频率。

## 系统调度记录

以下为轨迹覆盖的配对执行区间，按线程实际运行时间加权的频率；不是设备标称频率或全时段最高频率。

| 阶段 | 一加实际运行位置与频率 | 三星实际运行位置与频率 |
|---|---|---|
| 原生 JPEG 工作 | 几乎全部在 CPU 0–5，约 2340.839 MHz | 主要在 CPU 6、7，约 3624.141 MHz |
| 解码后到预览就绪 | 主要在 CPU 0、1，约 2355.799 MHz | 已覆盖的运行均在 CPU 6、7，约 3785.213 MHz |

这确定了两台设备在本次执行中的核心选择与频率差异。尚未进行单独改变调度条件的 A/B，不把这两个实测差异写成已隔离验证的唯一因果。

### `_R9A8705.JPG` 配对样本

三星文件名带复制后缀，源尺寸与字节数匹配，原生输出均为 1762×2491。

- 一加原生解码 150.860 ms，CPU 149.000 ms；运行主要落在 CPU 3，约 149.033 ms。解码后阶段主要在 CPU 0，Running 69.919 ms。
- 三星原生解码 89.090 ms，CPU 85.997 ms；运行主要落在 CPU 7，约 72.913 ms。解码后阶段在 CPU 7，Running 15.657 ms。
- 两侧绝大多数源线程执行的 sched priority 均为 129。该样本的核心分配差异发生在相同主要调度优先级下。

后续需要在一加任务执行期间读取 CPU 允许集合、cpuset/uclamp、频率上限和性能/温控状态，并对诊断包单独改变源线程调度条件复测。后处理还需统一输出尺寸并补函数计时。当前没有这些受控复测结果。

## 呈现时间与证据缺项

按请求匹配预绘制帧与 SurfaceFlinger 呈现帧，在 35 组文件中取得 31 组双方都有对应记录的样本。预绘制到系统呈现的中位数为一加 25.493 ms、三星 14.775 ms。这是系统轨迹呈现时间，未使用屏幕实拍。

三星有部分分段缓冲丢弃记录，trace-004 还有 4 条 systrace_parse_failure；帧关联、调度与频率结果只取有记录的区间。所有应用请求时间分别保留，没有把缺失帧补算为正常。

三星监听已停止，8 份轨迹均保存到本地。逐个核对大小后删除了手机上对应的临时轨迹副本，共 299,948,477 字节，本地文件完整保留。未修改用户图片。
