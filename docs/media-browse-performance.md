# 媒体分类计算优化

日期：2026-10-17。优化前版本：`ff3dab0b`。

## 实现

- 在 ViewModel 中把排好顺序的媒体快照转换为一代不可变的分类索引。全部、图片、视频共享媒体对象与缩略图条目，分类切换直接取现有列表。
- 日期格式化从每条媒体一次，改为每个不同日期／月份一次。主页与相册使用同一套时间与排序规则。
- 按完整相册路径建立索引，首次进入相册准备三个分类结果，再次进入或切换类型复用结果。
- 相册封面、数量、日期及各排序结果基于对应分类的媒体计算。相册排序变化只重新排序相册列表。
- 文件搜索和相册名称搜索分开计算。搜索保留当前类型顺序、剔除空日期标题，并支持取消旧任务。
- 滚动条的日期标签在后台准备并缓存；普通浏览不生成快速整理的整张 ID 表。
- 文件内容、路径、可见性、照片排序、日／月分组规则变化时重新生成索引。总条数不作为缓存有效性判断；移动文件但总数不变也会更新。恢复前台时检查系统时区。
- 打开相册大图前同步当前显示列表，避免导航读取尚未更新的旧分类结果。

## 15 万条记录的计算对比

环境：独立 SelectAllShot 模拟器，Android API 36，x86_64，debug 构建。
数据：内存中合成 150,000 条 MediaEntry，400 个相册，图片占三分之二、视频占三分之一，按日期降序排列。

测试先预热两轮，再取五轮计时的中位数。旧路径按优化前的筛选、相册汇总、再次排序及逐项日期格式化执行，并校验新旧网格结果一致。

| 项目 | 计时 |
|---|---:|
| 新索引首次构建，包含三种分类及相册统计 | 791.5488 ms |
| 旧逻辑重算“全部” | 1102.8225 ms |
| 旧逻辑重算“图片” | 721.1014 ms |
| 旧逻辑重算“视频” | 352.7082 ms |
| 已有缓存取值：全部 | 0.0021 ms / 次 |
| 已有缓存取值：图片 | 0.0025 ms / 次 |
| 已有缓存取值：视频 | 0.0019 ms / 次 |
| 375 条记录的相册首次准备，单次计时 | 1.5235 ms |
| 已准备相册的分类取值 | 0.0022 ms / 次 |

缓存取值每轮调用 1,000 次，再换算单次耗时。上述数值仅衡量内存中的计算和缓存读取，不含 MediaStore／Room 加载、缩略图解码、Compose 布局与绘制，也不能代表手机上的整屏切换耗时。未测量峰值内存；缓存保留额外索引、列表引用与分组信息。

原始记录：`scratch/media-browse-performance.log`。可复跑 Android instrumentation 的 `media-performance` 套件；测量代码为 `MediaBrowsePerformanceChecks.kt`。该诊断不是 Jetpack Microbenchmark，也不是物理设备基准结果。

## 正确性验证

- 全部 123 项单元测试通过，新增覆盖缓存复用、完整相册路径、同数量移动与类型变化、各排序的封面和统计、夏令时／月分组、搜索交集及取消后重试。
- `media-types` 模拟器套件覆盖主页与相册列表联动、相册内独立及重入继承、筛选后全选、大图翻页和返回、空状态、明暗主题及大字体。
- 在真实 MediaStore 中将一张测试图片移到另一个相册，确认总条数不变，旧相册消失，目标相册的图片分类更新为三项。
