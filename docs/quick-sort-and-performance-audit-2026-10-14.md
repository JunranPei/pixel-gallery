# Quick sort 与 Performance 核对记录

日期：2026-10-14。基于当前工作区和本地 Git 历史核对；没有清除用户图库或应用数据。

## 十万文件主页进入详情页变慢

原来的 `remapMovedViewerPhotos` 对每张图片遍历整份移动记录，且每次进入 Viewer 都对当前列表、实时列表各做一次。随后还在主线程建立整份 ID 映射、复制列表和比较内容。开销随图片数量及历史记录数量相乘增长。清除数据清空历史，几百张的相册列表也小得多，这与反馈的规模差异相符。

已改为按源图片 ID 和路径查找的索引，按原记录顺序处理连续移动和循环路径；没有实际变化时复用原列表。相同列表只处理一次；历史回放及元数据核对在后台执行，发布列表采用引用比较。

桌面 JVM 对比的是列表处理，不能作为手机首图加载时间。11 次预热后运行的中位数：

| 图片数量 | 历史记录 | 原实现 | 新实现 |
| ---: | ---: | ---: | ---: |
| 300 | 64 | 0.324 ms | 0.065 ms |
| 100,000 | 64 | 29.553 ms | 1.955 ms |
| 100,000 | 1,024 | 242.673 ms | 1.595 ms |

原始结果在 `scratch/viewer-entry-history-benchmark.csv`，比较程序在 `scratch/ViewerHistoryBenchmark.java`。未在用户手机的十万文件图库中复测黑屏时长。

## Persistent Grid Limit 与消失的选项

`2084c85a`（2026-10-05，设置卡片重排）把 Grid 滑块的保存函数从 `setGlidePersistentGridCacheSize` 改成了旧的 `setGlidePersistentCacheSize`。读取键和写入键不同，标题一直读取默认的 250 MB。已修正为 Grid 专用保存函数；模拟器实际操作后读回 1450 MB，旧通用设置值没有变化。

`1c4ade16`（2026-07-18，迁移大图渲染器）删除了以下五项页面控件及 ViewModel 接口：

| 旧选项 | 当前情况 |
| --- | --- |
| Persistent Viewer Limit | 旧设置键和旧预览缓存实现仍保留；当前普通图片路径不使用旧的持久预览链 |
| Large Image Decoder Threads | SSIV 使用独立的串行切片任务队列，不读取旧参数 |
| Large Image Tile Size | 当前 SSIV 最大切片固定为 1024 px，不读取旧参数 |
| Gestures Throttling Delay | 旧参数留在 Telephoto 实现中，未接入普通图片的 SSIV 路径 |
| Experimental Hardware Bitmaps | 旧参数留在 Telephoto 实现中，未接入普通图片的 SSIV 路径 |

该提交同时移除了 MainActivity 中把旧大图设置传给旧渲染器的订阅。现有 SSIV 磁盘切片缓存单独设置为 512 MB 上限、整理到 460 MB。这次没有恢复对当前渲染器无效的旧控件。

## 本次分拣撤回与利手

- 撤回按钮采用 Copy / Move 同款 56 dp 圆形胶囊，位于相册胶囊第一排上方。
- 相册胶囊、撤回、Copy 和 Move 共用持久化利手设置，默认右利手。Display 与 Theme mode 使用同一个选项组件。
- 撤回仅针对当前 quick sort 会话；退出模式、重新进入或重启后不能撤回上一轮。撤回任务自身不能再被撤回。
- 排队项目直接取消；正在移动的项目完成并保存记录后再反向移动；已完成项目恢复原目录、原文件名、内容和时间。
- 同名警告提供保留两份、跳过、替换，沿用 GalleryDialog 和既有选项 UI。替换权限规则与 Copy / Move 一致。
- 替换把目标原文件暂存到操作专属备份目录，保留内容和媒体身份；撤回先恢复移入文件，再恢复被替换文件。会话结束后清理经核对的已完成替换备份。未完成或需检查的备份继续保留。
- 原位置有同名文件、文件身份或内容变化时，停止对应撤回并显示现有警告 UI，保留需检查的位置。

## 失败记录处理

原实现的新重试任务没有关联旧失败项，成功后旧任务仍永久保留失败状态。现已保存逐项目的重试来源，核对成功后把对应旧项及中间失败重试标记为已处理；失败、取消、跳过或未通过核对的结果不清除旧错误。旧项保留在最近历史范围内，超过范围后可正常淘汰。

对于旧版本没有来源关联的记录，仅当后续成功任务的图片条目、目标目录、SHA-256、文件大小和修改时间吻合，而且没有另外留存的目标需要检查时，才补标为已处理。无法证明已处理的记录继续保留。

用户提交队列最多 20 批、1000 个项目；普通结束历史保留最近 30 批。未解决失败、未完成撤回及未释放备份保留证据，仍可能超过最近 30 批。撤回替换时每个用户项目可能对应两个反向文件操作。
